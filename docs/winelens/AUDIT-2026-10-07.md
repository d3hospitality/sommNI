## Findings

1. **Two competing account systems.** `codex/winelens-accounts` built `account.html` + Supabase Edge Functions (never deployed: zero functions on the project); `codex/winelens-tokens` built the website `/link` + Vercel API whose migrations are applied live. The unified branch keeps only the second.
2. **Winebrary pointed at the wrong database** (`sommni-api` → d3-shared by default; production `SUPABASE_URL` empty). A linked wineLENS account could not have saved a wine.
3. **Live wineLENS DB was missing** the `winelens-bottles` bucket/policies and `study_review_events`.
4. **Images were unmetered by tokens** and ran in a separate, undeployed API.
5. **Notes were not a product.** Nothing let you get notes for your own wine except scanning a label.
6. **Phone catalog hid the notes** and still carried restaurant inventory UI (stock ±, 85/86 filters, "Inventory alerts: all stocked up" on Home).
7. **Pricing sold a feature that did not exist** (wine-list pages: 5/month on Pro, 3 tokens each). Now built, at that price.
8. **Copy and polish:** "Upgrade on wineLENS.com" (not the domain), "TERrazas" on the hero, "Rose" instead of Rosé, "Mendoza, Argentina · Argentina", a user-visible Debug Log, seven tabs led by marketing, "Discover/Courses/Overview" naming, `[sommNI-TG]` log prefixes.
9. **Paid requests had no lost-response protection on the client:** every retry minted a new request ID, so a dropped response could charge twice.
10. **A test (`catalog-lifecycle`) hard-coded port 5186** and silently depended on another worktree's server.
11. **No shared wine identity.** Label scans, manual adds and the old list wizard each named and placed wines their own way, so the same bottle could land on different catalog rows, globe points or notes. The local SQL harness also guessed the wrong shape for the live ingest ("truth funnel") tables.

## What changed

**One backend.** The Vercel project `sommni` (`sommni-beige.vercel.app`) now serves every account call: `device-link`, `billing`, `stripe-webhook`, `winebrary`, `study`, `wine-scan`, `wine-notes`, `bottle-render`, `wine-list`, `catalog-review` (10 functions). Winebrary and study queries run with the caller's JWT so RLS enforces ownership; the service role only verifies the linked session and settles usage. `sommni-api` is now only used for voice transcription (and the Android app); its anonymous list parsers are superseded by `/api/wine-list`. `integrations/sommni-api/` was removed.

**Database** · `supabase/migrations/20261007190000_winelens_winebrary_ai.sql` (additive, **not applied**):
- `user_collection` grants, `winelens-bottles` private bucket with read/insert/**delete**-own policies, `study_review_events`.
- Rate card **v2**: `tasting_notes` (5 free · 60 Pro · 1 token), `wine_list_page` (1 · 5 · 3 tokens a photo page), `wine_list_text` (20 · 100 · 1 token per 6,000-character page). v1 stays immutable; pack grants still validate against v1 (packs are identical).
- `winelens_reserve_usage` accepts exactly the features on the current card (was a hard-coded list) and returns the token `cost` on consent/limit refusals.
- `winelens_ai_jobs` + `winelens_begin_job(…, p_quantity 1–20)` / `winelens_finish_job` (service role only): a multi-page list is one job, the allowance covers what it can and the rest is tokens per page (Free cannot top up); request ID bound to an input fingerprint; replay returns the stored result; the charge and result commit together; a failure releases the allowance/tokens.
- `winelens_shared_notes` + `winelens_share_claim` / `_fill` / `_release` (service role only): one row per bottle + vintage, keyed by sha256 of normalised producer | wine | vintage ("Terrazas de los Andes Grand Malbec" = "Grand Malbec" by Terrazas; "Wine – Producer" catalog names are split). A ready row is returned free; a claim in progress makes others wait (409, not charged); a refused or failed draft releases the bottle; claims older than 5 minutes can be taken over. Wines with no producer are never shared. Notes contain wine facts only and outlive the account that paid for them (owner set to null).
- `winelens_list_uploads` / `winelens_list_entries` (each wine as read + how it resolved + saved/skipped), `winelens_catalog_proposals` + `winelens_propose_wine` / `winelens_decide_proposal`. Approval inserts into `public.wines` and records the decision in the live truth-funnel tables (`ingest_batches` / `ingest_wines_raw`), like any other ingest. All service-role only.

**Wine lists** (`server/wine-identity.cjs`, `server/wine-list.cjs`, `src/wine-list.ts`)
- **One resolver for every wine.** Catalog: exact producer + wine key, else a close spelling of the same producer (never a different producer); single-column lines ("Terrazas de los Andes Grand Malbec") have a known producer peeled off only when that lands on its catalog wine. Globe: catalog regions, 24 curated aliases (`shared/region-aliases.json`) and 2,077 winery clusters, with core forms ("Maipo Valley" = "Valle del Maipo", "Russian River Valley AVA" = "Russian River"), "Napa, CA" = California, and a country written with the place winning over a stale country field. Anything else is marked **not on the globe yet**, never guessed. Keys: the same producer + wine + vintage gives the same shared-notes key however it is written. Data is generated by `scripts/build-wine-index.mjs`.
- **Sources.** Photos (shrunk on the phone to ≤ 450 KB, up to 6 pages), PDFs (free server check for a text layer; scans are sent back to photos), pasted text, CSV (named columns, no AI, free; Excel asks for CSV). A read that finds no wines is not charged.
- **Review.** Grouped *In the wineLENS catalog* / *New to wineLENS* / *Needs a look*, with chips for catalog match, place on the globe, notes ready (catalog or already drafted, free), already in your Winebrary, listed N×, hard to read. Inline edits; on save the server re-resolves every field and keeps a catalog link only if it is still the same wine. A paid read stays in the account: *Continue your last list*.
- **Catalog growth.** New wines (with a producer) become suggestions, counted per save. The owner sees them in the account dialog (*Review catalog suggestions*, plan `owner` only), with the places that still need an alias; approve (optionally corrected) or reject.

**Glasses bottles from the backend** (8 Oct, `scripts/build-g2-bottles.py`, `src/bottle-assets.ts`)
- The glasses used to download the full colour photograph (~160 KB) for every bottle they drew. The backend now serves one glasses-ready image per catalog wine at `/g2/bottles/<catalog id>.png`: greyscale + alpha, trimmed, 420 px tall, **~22 KB** (214 wines, 4.8 MB in total), plus `index.json`. Same tone mapping, stage light and reflection on the phone, so they look identical (`test:bottles` renders all 214 both ways: same lit pixels within 8%).
- Named by catalog ID, so a wine added to the catalog gets its bottle without an app update. The bundled photograph is the fallback; if the backend is unreachable it is skipped for a minute (one failed request, never a stall). CORS + cache headers in `vercel.json`.
- Used everywhere the glasses draw a bottle: tasting notes, finder results, Atlas, Study, Winebrary. **Winebrary wines saved from the catalog without your own photo now show their catalog bottle** (glasses and phone, labelled "Catalog photograph · label year may differ").
- `w105` (the manifest's unresolved Pahlmeyer vs Jayson label) is held back everywhere instead of risking the wrong bottle.

## Not done / worth deciding

- **Voice search** still calls `sommni-api /api/transcribe` anonymously: unmetered OpenAI cost. Put it behind the account (or a hard rate limit) before a public launch.
- **Wine-list text pages are metered (a deviation from your answer).** You picked "per page with tokens" whose description said text PDFs and spreadsheets are free. Spreadsheets are free (no AI). PDF text and pasted lists still go to OpenAI, so an unmetered 60,000-character list could cost real money per upload; they get their own, generous allowance instead: **20 text pages free, 100 on Pro, then 1 token per ~6,000 characters**. To make them free, set `wine_list_text` to a large allowance in rate card v3.
- **Retire `sommni-api`'s anonymous `parse-winelist` / `parse-images`** once `/api/wine-list` is live: they run OpenAI for anyone.
- **Approved suggestions reach `public.wines`, not the app's bundled catalog.** The phone and glasses read the bundled catalog, so an approved wine shows up in the app after the next catalog release (export → app catalog → `build-wine-index --write`). Until then, people who saved it keep it in their Winebrary.
- **Places not on the globe** are listed in the owner review; fixing one is a line in `shared/region-aliases.json` (plus a rebuild), deliberately a reviewed code change.
- **Shared notes are free to everyone after the first payer.** Alternative if you prefer revenue over goodwill: still charge an allowance use (no tokens) for reused notes. One-line change in `server/ai-jobs.cjs`.
- **Notes pricing** (5 free · 60 Pro · 1 token) is my call, mirroring scans. Change by inserting rate card v3 + editing `shared/rate-card.json`; no code change.
- Older G2 navigation items from the deep audit (some legacy lists, rebuild rejections) are covered by `CATALOG-RELIABILITY.md`; not re-audited here beyond the passing suites.
- **Old Studio RPCs** `winelens_reserve_studio` / `winelens_settle_studio` (from the tokens migration) are still callable by signed-in users. Not exploitable (they only reserve/release the caller's own allowance) and now unused: the new `/api/bottle-render` uses the service-only job functions. Revoke `execute` from `authenticated` in a follow-up. The 0004 `winelens_import_wines` / `winelens_update_wine_notes` RPCs are token-gated but callable by `anon`; they belong to the old ingest wizard and go with it.
- Housekeeping: 14 empty Vercel projects `sommni-web-v8 … v22`; branch `codex/winelens-accounts` (competing accounts) can be retired; `sommni-api` has 40 uncommitted files now superseded for Winebrary/Studio/study.
