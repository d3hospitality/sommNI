## Findings

1. **Two competing account systems.** `codex/winelens-accounts` built `account.html` + Supabase Edge Functions (never deployed: zero functions on the project); `codex/winelens-tokens` built the website `/link` + Vercel API whose migrations are applied live. The unified branch keeps only the second.
2. **Winebrary pointed at the wrong database** (`sommni-api` → d3-shared by default; production `SUPABASE_URL` empty). A linked wineLENS account could not have saved a wine.
3. **Live wineLENS DB was missing** the `winelens-bottles` bucket/policies and `study_review_events`.
4. **Images were unmetered by tokens** and ran in a separate, undeployed API.
5. **Notes were not a product.** Nothing let you get notes for your own wine except scanning a label.
6. **Phone catalog hid the notes** and still carried restaurant inventory UI (stock ±, 85/86 filters, "Inventory alerts: all stocked up" on Home).
7. **Pricing sold a feature that does not exist** (wine-list pages: 5/month on Pro, 3 tokens each).
8. **Copy and polish:** "Upgrade on wineLENS.com" (not the domain), "TERrazas" on the hero, "Rose" instead of Rosé, "Mendoza, Argentina · Argentina", a user-visible Debug Log, seven tabs led by marketing, "Discover/Courses/Overview" naming, `[sommNI-TG]` log prefixes.
9. **Paid requests had no lost-response protection on the client:** every retry minted a new request ID, so a dropped response could charge twice.
10. **A test (`catalog-lifecycle`) hard-coded port 5186** and silently depended on another worktree's server.

## What changed

**One backend.** The Vercel project `sommni` (`sommni-beige.vercel.app`) now serves every account call: `device-link`, `billing`, `stripe-webhook`, `winebrary`, `study`, `wine-scan`, `wine-notes`, `bottle-render` (8 functions). Winebrary and study queries run with the caller's JWT so RLS enforces ownership; the service role only verifies the linked session and settles usage. `sommni-api` is now only used for voice transcription (and the Android app). `integrations/sommni-api/` was removed.

**Database** · `supabase/migrations/20261007190000_winelens_winebrary_ai.sql` (additive, **not applied**):
- `user_collection` grants, `winelens-bottles` private bucket with read/insert/**delete**-own policies, `study_review_events`.
- Rate card **v2** (`tasting_notes` in, `wine_list_page` out). v1 stays immutable; pack grants still validate against v1 (packs are identical).
- `winelens_reserve_usage` accepts exactly the features on the current card (was a hard-coded list) and returns the token `cost` on consent/limit refusals.
- `winelens_ai_jobs` + `winelens_begin_job` / `winelens_finish_job` (service role only): request ID bound to an input fingerprint; replay returns the stored result; the charge and result commit together; a failure releases the allowance/tokens.

**Phone**
- Tabs: Home · **Wines** · Winebrary · Study · Pairings · Dinner · Settings. The Atlas card moved to Home; Home shows catalog/Winebrary/favorites/pairings and "Browse by style" chips that open the catalog. Inventory UI removed (parked for the venue edition; `sync.ts` storage untouched).
- Winebrary wine page: notes block with source label (Your notes / label-scan draft / wineLENS notes / catalog notes), **✦ Draft tasting notes**, photo + Studio, glasses preview, add vintage.
- One cost panel for scan, notes and Studio: "Free · 4 of 5 left", "Included with Pro · 9 of 10 left", "Pro allowance used · uses 8 tokens (42 left)" + an explicit tick (or Always allow), or a link to Pro / buy tokens. Buttons stay disabled until the cost is accepted.
- Paid request IDs are kept only when the response never arrived, so a retry replays for free.
- Account dialog shows plan, tokens and each allowance. Developer log is folded away.

**Glasses** · Winebrary pages use the same notes layout and source footers; catalog twins show catalog notes instead of "No notes yet". Signed-out/empty messages updated. Beta version **3.3.0**.

**Site and legal** · Pricing reads the v2 card automatically. Terms, privacy and FAQ now describe drafted tasting notes (what is sent to OpenAI: wine identity only, not photos or your notes) and drop wine-list pages.
