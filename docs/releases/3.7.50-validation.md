# sommNI 3.7.50 beta

Winebrary photo recovery is visible without opening notes or expanding a bottle row. A compact gold-accented summary offers a Missing Photos filter and Find Photos action. Filtering respects the current country, region and text search. Rows and bottle cards expose the same direct Find Photo entry; completed bottles keep their existing quiet layout.

A single missing bottle opens the existing three-candidate studio. Multiple missing bottles start the existing shared label queue for the first ten wines in the current scope; clipping/saving still requires a deliberate choice. Server-side daily allowances are unchanged. Catalog-linked artwork counts as present and is reused. Failed URLs become actionable locally without clearing or deleting their stored source; Refresh retries them, a new URL is recognized, and account changes reset the failure/filter state.

Batch review adds Previous and Upload My Photo. Upload opens the existing photo/camera studio without issuing another discovery lookup. A successful phone upload updates the same queue observed by G2, including its saved state and new image. Late search results/errors cannot overwrite that save, and disposed/account-changed queues ignore it. Existing Supabase attachment, local artwork, shared master contribution and glasses raster paths are reused. No backend, permission, whitelist, allowance or master deletion policy change.

Validation: 38 serial beta checks, both TypeScript projects, site build, package build and client URL audit. New integration tests exercise the production Winebrary rendering: scoped filters, collapsed row/card actions, single vs ten-bottle search, catalog reuse, completion escape, failed-image recovery without data deletion, fresh URLs and account reset. Studio tests cover upload-only entry without another lookup; queue tests cover manual-upload adoption and late-search races; G2 tests verify that the uploaded image reaches active review, page limits, three-option selection, explicit save and graceful Back.

An existing discovery-test race was corrected: its mocked vision result now judges the candidate image bytes rather than assuming the second concurrent request is the correct photograph. Production discovery code is unchanged.

Portrait Chrome QA at 390x844 used an isolated, labeled fixture with sample wines and mocked network/persistence. Verified Missing Photos/Show All Wines, direct studio entry, three candidates, compact rows and consistent controls. Fixture files were removed and are not packaged. No real wine/profile/account changes or paid provider calls were made during QA. Physical G2 hardware was not connected; display behavior was checked through the real controller with a simulated bridge.
